# Hermes 스킬로 조사부터 웹 배포까지 맡기기

비개발자와 초급 개발자 | 기본 실습 135분, 심화 선택 20분, 휴식 10분

내 소개 사이트에 문의 기능을 붙이고, 모임 신청을 저장하고, 만든 페이지를 공유해 봅니다. 내 프로젝트 진행 원칙을 기억시키고 소개 영상도 만듭니다. 마지막에는 마음에 드는 공개 사이트의 신청 흐름을 읽어 내 사이트에 적용합니다. 각 실습은 따로 마칠 수 있습니다. 같은 소개 사이트가 있으면 문서 조사, 배포, 영상과 사이트 분석에 이어서 써도 됩니다.

## 01. 내 일에 필요한 스킬 고르기 (10분)

저는 도구를 고를 때 설치한 개수보다 어떤 일이 쉬워졌는지를 먼저 봅니다. 이번에도 “최신 설명서를 찾아야 한다”, “다른 사람에게 주소를 보내야 한다”처럼 끝내고 싶은 일에서 시작합니다. 스킬은 에이전트가 그 일을 처리할 때 읽는 절차와 판단 기준입니다. 설치만으로 계정 권한이나 실행 도구가 생기지는 않습니다.

| 구분 | 뜻 | 오늘의 예 |
|---|---|---|
| builtin | Hermes가 기본 제공하는 스킬 | 전체 목록의 Source가 builtin인 항목 |
| 설치형 | 검토한 공개 저장소에서 추가하는 스킬 | context7-cli, supabase, vercel-cli, hyperframes-cli, reverse-engineer-anything |
| 직접 만든 스킬 | 자신의 반복 업무 기준을 정리한 것. 공개하면 다른 사람도 설치 가능 | hermes-hermory |

### 오늘 고른 실습과 남길 결과

| 필요한 일 | 사용할 스킬 | 남길 결과 |
|---|---|---|
| 최신 설명서를 읽고 문의 기능 붙이기 | context7-cli | 문의 화면, 필요한 연결 안내와 문서 출처 |
| 독서모임 참가 신청 받기 | supabase | 신청 페이지와 운영자 전용 명단 |
| 내 포트폴리오를 지인에게 보내기 | vercel-cli | 다른 사람이 열 수 있는 실제 주소 |
| 기능 추가 전 물을 질문 기억시키기 | hermes-hermory | 새 대화에도 적용되는 프로젝트 진행 원칙 |
| 내 프로젝트 소개 영상 만들기 | hyperframes-cli | 세 장면의 미리보기와 15초 영상 |
| 좋은 사이트의 신청 흐름 배우기 | reverse-engineer-anything | 내 사이트에 참고할 구성안, 심화 선택 |

수강생이 말할 것은 하려는 일, 가진 자료, 원하는 결과입니다. 사용할 라이브러리나 데이터 필드 이름은 에이전트가 현재 프로젝트를 읽고 정하게 합니다. 모르는 준비가 나오면 한 가지씩 질문받아 진행하세요. 계정 로그인과 키 입력은 본인의 설정 화면에서 하고, 채팅에 비밀키를 붙이지 않습니다.

### 사용 중인 Hermes에서 시작하기

기존 수업 프로필 `jiwon`을 사용합니다. [Hermes 설치와 첫 대화](https://teamsparta.habix.ai/teamsparta/10th/setup/hermes)를 먼저 마칩니다. 다른 프로필을 이미 사용한다면 실제 ID를 확인하고 아래 `-p jiwon`을 같은 ID로 바꿉니다. 새 프로필을 만들 필요는 없습니다.

현재 프로젝트의 터미널에서 대화를 엽니다. 이미 같은 프로필의 대화창이 열려 있다면 그대로 사용합니다.

```bash
hermes -p jiwon chat
```

Hermes 대화창에서 사용할 프로필과 모델을 확인합니다.

```text hermes
/status
```

`Path:`와 `Model:`을 읽습니다. 설치 확인은 터미널에서 전체 목록을 봅니다. `--source local`로 범위를 좁히지 않습니다.

```bash
hermes -p jiwon skills list
```

`skills_list`는 에이전트 내부 도구입니다. 대화창에서는 “skills_list로 현재 스킬을 확인해 줘”라고 요청할 수 있습니다. 아래의 `/스킬이름 요청`은 Hermes 대화창에, `hermes ...` 명령은 터미널에 입력합니다. 같은 스킬이 이미 있으면 재설치하지 않습니다. 설치 후 `/exit`로 나간 뒤 같은 터미널에서 `hermes -p jiwon chat`으로 새 대화를 엽니다. 검사 차단을 `--force`로 우회하지 않습니다.

| 실습 | 먼저 준비할 것 |
|---|---|
| 문의 기능, 포트폴리오 배포 | Hermes가 읽고 고칠 수 있게 열어 둔 소개 페이지 파일 |
| 모임 신청 | 연결된 본인 Supabase 실습 프로젝트, 운영자로 사용할 본인 로그인 계정 |
| 배포 | 본인 Vercel 계정과 배포 도구 로그인 |
| 기억 | 현재 프로필의 메모리 도구 |
| 영상 | 소개할 화면 캡처, HyperFrames 실행 도구와 브라우저, 렌더용 FFmpeg |
| 사이트 분석 | 공개 URL, REA의 웹 분석 도구 |

[Supabase 연결 준비](https://teamsparta.habix.ai/teamsparta/10th/setup/supabase) | [Vercel 로그인 준비](https://teamsparta.habix.ai/teamsparta/10th/setup/vercel) | [Node.js 준비](https://teamsparta.habix.ai/teamsparta/10th/setup/node)

소개 페이지가 없다면 아래 요청부터 합니다. 별도 이름의 실습 폴더나 파일 묶음을 먼저 만들 필요는 없습니다.

```text hermes
소개 사이트가 아직 없어. 간단한 소개 페이지를 만들 수 있게 소개 문구와 보여줄 프로젝트를 하나씩 물어봐줘. 답을 바탕으로 페이지를 만들되 저장 위치를 먼저 알려주고 기존 파일은 덮어쓰지 마.
```

실습에는 가상 이름과 자료를 사용합니다. 실제 고객 정보나 회사 내부 자료는 넣지 않습니다. 아래 결과 예시는 모양을 설명하기 위한 것이며, 자신이 받은 실제 파일과 주소를 열어 완료 여부를 판단합니다.

## 02. context7-cli: 내 소개 사이트에 문의 기능 붙이기 (20분)

AI가 기억하는 예전 방법으로 만들면 화면은 있어도 버튼이 동작하지 않을 수 있습니다. Context7은 현재 프로젝트에 맞는 라이브러리 문서를 찾는 역할입니다. 구현과 계정 연결은 Hermes의 파일·실행·연결 도구가 맡습니다. 수강생이 버전 이름이나 호출 방법을 지정할 필요는 없습니다.

설치, 터미널:

```bash
hermes -p jiwon skills install upstash/context7/skills/context7-cli
hermes -p jiwon skills list
```

목록에서 `context7-cli`를 확인합니다. 준비 자료는 현재 소개 페이지입니다. 파일 위치를 Hermes가 모르면 열어 둔 프로젝트나 파일을 먼저 지정합니다.

### 1. 만들고 싶은 기능 말하기

```text hermes
/context7-cli 지금 만드는 소개 사이트에서 방문자가 문의를 남길 수 있게 하고 싶어. 현재 사용하는 도구에 맞는 최신 공식 문서를 찾아줘. 내가 준비할 계정이나 정보가 있다면 쉬운 말로 한 가지씩 알려줘.
```

받을 답은 문서 제목 나열이 아니라 내 페이지에서 가능한 방법과 필요한 준비입니다. 새 프로젝트라 확인할 패키지가 없으면 에이전트가 사용할 도구를 먼저 설명하게 합니다. 문서의 버전과 프로젝트가 다르면 그 차이도 알려 달라고 하세요.

### 2. 문의 화면 만들기

```text hermes
알아본 방법으로 내 소개 페이지에 문의 양식을 만들어줘. 이름, 연락받을 이메일, 문의 내용을 받고, 비어 있는 항목과 제출 중인 상태, 실패했을 때 다시 시도하는 방법을 화면에 보여줘. 기존 화면은 유지해줘.
```

문의 양식이 보인다고 문의가 전달되는 것은 아닙니다. 어디로 접수할지 에이전트에게 확인받고 실제 연결로 이어갑니다.

```text hermes
이 문의가 실제로 어디에 접수되는지 알려줘. 연결된 곳이 없으면 사용할 방법과 필요한 준비를 한 가지씩 물어봐줘. 내가 대상을 확인하면 연결해줘. 연결 전에는 접수 완료라고 표시하지 마.
```

외부 계정 연결이 필요하면 본인이 준비한 실습 계정을 사용합니다. 실제 사람에게 메일을 보내는 방법은 수신 대상과 발송 내용을 별도로 확인하고 선택합니다.

### 3. 가상 문의 한 건 남기기

```text hermes
지금 만든 페이지를 브라우저에서 열 수 있게 실행하고 실제 주소를 알려줘. “연습 방문자, visitor@example.com, 프로젝트 시연을 보고 싶어요”로 문의하는 순서와 접수 내용을 내가 확인할 위치를 안내해줘.
```

5분 미니 실습: 실제 주소에서 빈 양식을 한 번 제출해 보고, 가상 문의를 입력해 제출합니다. 접수 위치에서 같은 내용이 있는지 확인합니다. 연결하지 못했다면 양식 완성과 접수 미연결을 구분해 남깁니다.

```text output
화면: 이름, 이메일, 문의 내용과 제출 버튼
입력 누락: 무엇을 채워야 하는지 표시
제출 중: 진행 상태 표시
접수 결과: 실제 연결한 곳에서 같은 문의 확인
미연결 상태: 접수 완료로 표시하지 않음
```

막히면: 공식 문서를 찾지 못하면 현재 프로젝트가 쓰는 도구부터 확인하게 합니다. 요청 제한은 안내된 시간 뒤 재시도합니다. 문의가 안 보이면 실패 메시지를 그대로 전달하고 어디까지 처리됐는지 묻습니다. 문서 출처와 에이전트가 고친 파일 위치를 함께 남기세요.

완료 확인: 내 소개 페이지의 문의 양식을 열고 가상 문의를 제출했습니다. 실제 접수 또는 아직 연결하지 못한 상태를 구분했습니다.

다음에 더 찾아볼 것: [Context7 공식 문서](https://github.com/upstash/context7/blob/master/docs/clients/cli.mdx).

## 03. supabase: 독서모임 참가 신청 받기 (35분)

새로고침할 때 신청 내용이 사라지면 운영자는 명단을 관리할 수 없습니다. Supabase는 정보를 보관하는 Database, 로그인한 사람을 구분하는 Auth, 서버 처리가 필요할 때 쓰는 Edge Functions를 제공합니다. 이번 실습의 기준은 “신청은 방문자가 하고 명단은 운영자인 나만 본다”입니다.

설치, 터미널:

```bash
hermes -p jiwon skills install supabase/agent-skills/skills/supabase
hermes -p jiwon skills list
```

목록에서 `supabase`를 확인합니다. 연결된 본인 실습 프로젝트를 사용합니다. 없으면 [Supabase 연결 준비](https://teamsparta.habix.ai/teamsparta/10th/setup/supabase)를 먼저 마칩니다. 스킬 설치와 내 계정 연결은 별개입니다.

### 1. 받을 정보와 볼 사람 정하기

```text hermes
/supabase 독서모임 참가 신청을 받고 싶어. 닉네임, 이메일, 관심 주제를 입력하게 해줘. 신청자는 다른 사람의 명단을 볼 수 없고 운영자인 나만 확인해야 해. 먼저 만들 화면과 저장할 내용을 쉬운 말로 정리해줘.
```

운영자로 사용할 본인 로그인 계정을 에이전트가 확인하게 합니다. 로그인한 모든 사람이 운영자가 되는 구조는 사용하지 않습니다. 새로 만들 실습 범위와 사용할 프로젝트가 맞는지 읽은 뒤 진행합니다.

### 2. 신청 화면과 운영자 명단 만들기

```text hermes
그 구성으로 연결된 내 실습 프로젝트에 만들어줘. 운영자는 내가 지정한 로그인 계정 한 개로 하고 필요하면 나에게 확인해줘. 명단을 화면에서만 숨기지 말고 다른 사람은 데이터 자체를 읽지 못하게 해줘. 기존 자료는 바꾸지 마.
```

계정의 연결 도구로 작업할 수 없으면 필요한 설정이나 Dashboard 작업을 한 단계씩 안내받습니다. 비밀키를 대화에 넣어 해결하지 않습니다. 저장할 항목, 접근 권한과 코드는 에이전트가 작성하고, 수강생은 누가 신청하고 누가 명단을 볼지 판단합니다.

```text hermes
만든 신청 페이지와 운영자 화면을 브라우저에서 열 수 있게 실행하고 실제 주소를 알려줘. 내가 운영자로 로그인하는 방법도 안내해줘. 가상 신청을 한 뒤 어디서 확인하면 되는지 보여줘.
```

### 3. 가상 참가 신청 세 건으로 사용하기

아래는 대화에 전달할 가상 신청 자료입니다. 실제 참가자의 정보는 사용하지 않습니다.

| 닉네임 | 이메일 | 관심 주제 |
|---|---|---|
| 참가자A | reader-a@example.com | AI와 일하는 방법 |
| 참가자B | reader-b@example.com | 책을 읽고 실천하는 방법 |
| 참가자C | reader-c@example.com | 함께 프로젝트 만드는 방법 |

5분 미니 실습: 신청 페이지에서 세 건을 직접 등록하고 운영자 계정으로 명단을 엽니다. 새로고침한 뒤에도 같은 신청이 있는지 봅니다. 별도의 시크릿 창에서는 다른 사람 명단을 읽을 수 없어야 합니다.

```text hermes
내가 입력한 가상 신청 세 건이 운영자 명단에 남는지 확인해줘. 로그아웃한 방문자와 운영자가 아닌 계정은 명단을 읽거나 수정할 수 없어야 해. 기존 신청은 삭제하지 말고 결과와 내가 확인할 화면을 알려줘.
```

운영자와 다른 로그인 계정이 없다면 그 계정의 확인은 아직 하지 못한 것으로 남기고, 에이전트에게 권한을 확인할 방법을 묻습니다. 화면에 명단 메뉴가 없다는 이유만으로 데이터 접근까지 막혔다고 판단하지 않습니다.

```text output
신청자: 신청 양식을 작성하고 접수 결과를 봄
운영자: 로그인 후 가상 신청 세 건을 확인
새로고침: 같은 신청이 유지됨
그 밖의 방문자: 다른 사람 명단 조회·수정 불가
```

<details>
<summary>AI가 처리하는 기술은 무엇인가요?</summary>

Database는 신청 내용을 저장합니다. Auth는 로그인 계정을 확인합니다. RLS와 데이터 권한은 그 계정이 어떤 내용을 읽고 쓸 수 있는지 정합니다. 운영자 권한은 방문자가 스스로 바꿀 수 있는 값으로 결정하지 않습니다. 클라이언트용 공개키와 서버 비밀키도 구분해야 합니다.

추가·조회·수정·삭제를 CRUD라고 부릅니다. 이번에는 신청 추가와 명단 조회를 먼저 완성합니다. 신청 취소나 정보 수정이 필요해지면 누가 자기 정보를 바꿀 수 있는지 정한 뒤 확장합니다. Edge Function은 브라우저에 둘 수 없는 처리나 서버 검사가 생길 때 사용하는 선택 확장입니다.

</details>

막히면: 저장이 안 되거나 명단 접근이 막히면 에이전트에게 실제 오류를 전달합니다. 접근 규칙을 전부 끄게 하지 말고 해당 작업에 필요한 권한만 고치게 합니다. 운영자 로그인과 프로젝트가 맞는지 먼저 확인하세요.

완료 확인: 가상 신청이 저장되고 운영자가 다시 읽었습니다. 명단의 다른 사람 접근 차단을 확인한 범위도 구분했습니다.

다음에 더 찾아볼 것: [Supabase 데이터 접근 규칙](https://supabase.com/docs/guides/database/postgres/row-level-security).

## 04. vercel-cli: 내 포트폴리오를 지인에게 보내기 (20분)

로컬 화면을 캡처해서 보내면 지인은 버튼을 눌러 볼 수 없습니다. Vercel로 배포하면 브라우저에서 열 수 있는 실제 주소를 받습니다. Preview는 정식 공개 전에 확인하는 별도 배포입니다. 도구와 본인 계정 로그인이 준비돼 있어야 합니다.

에이전트가 보여준 대상과 공개 파일을 읽습니다. 키, 계정 설정이나 개인 자료가 섞여 있지 않은지 확인하고, 맞으면 같은 대화에서 승인합니다.

```text hermes
보여준 계정과 공개 파일을 확인했어. 그 범위로 미리보기 배포를 진행하고 실제 주소를 알려줘. 기존에 공개한 다른 사이트는 바꾸지 마.
```

```text hermes
방금 배포한 주소를 휴대폰에서 열 때 확인할 것 세 가지만 알려줘. 지인도 로그인 없이 열 수 있는지 확인하고, 접근 권한이 필요하다면 내가 공유할 수 있는 방법을 설명해줘.
```

5분 미니 실습: 실제 주소를 다른 창이나 휴대폰에서 엽니다. 소개 문구, 프로젝트 카드와 문의 버튼을 봅니다. 메신저로 보내기 전에는 주소를 직접 복사해 새 창에서 열어 보세요. 공유나 메신저 전송은 수강생이 직접 합니다.

```text output
남길 주소: 배포 도구가 반환한 실제 Preview URL

공유 조건: 로그인·초대가 필요한지 구분
```

막히면: 다른 페이지가 나오면 배포한 프로젝트가 맞는지 확인합니다. 로컬에서는 되는데 배포 후 연결이 안 된다면 아래처럼 요청하세요.

```text hermes
로컬에서는 되는데 방금 배포한 주소에서는 동작하지 않아. 실제 오류와 배포 기록을 읽고 필요한 수정 한 가지를 먼저 설명해줘. 설정값이나 비밀키는 출력하지 마. 내가 확인하면 고치고 새 주소에서 다시 확인해줘.
```

<details>
<summary>환경변수와 로그는 언제 필요한가요?</summary>

환경변수는 실행 환경에 전달할 설정입니다. 브라우저에 전달되는 공개 설정과 서버 비밀값은 구분해야 합니다. 환경변수를 바꿔도 이미 만든 배포에 자동 반영되는 것은 아니므로 새 배포를 확인합니다.

Build Logs는 배포를 준비하다 실패했을 때, Runtime Logs는 배포 후 서버 실행 오류를 조사할 때 읽습니다. 정적 페이지의 브라우저 오류는 브라우저 콘솔에서 확인합니다. 에이전트에게 실제 주소와 오류를 전달하면 어느 기록을 읽을지 판단하게 할 수 있습니다.

</details>

완료 확인: 다른 창에서 포트폴리오의 실제 주소를 열었습니다. 공개된 내용과 지인의 접근 조건을 확인했습니다.

## 05. hermes-hermory: 기능 추가 전 물을 질문 기억시키기 (15분)

기능을 떠올릴 때마다 바로 만들기 시작하면 정작 누구의 불편을 해결하는지 놓치기 쉽습니다. 이번에는 “사용자가 언제 불편하고 지금은 어떻게 해결하는가”를 먼저 묻는 원칙을 기억시킵니다. 일회성 할 일이 아니라 다음 프로젝트에도 쓸 진행 기준입니다.

메모리는 여러 대화에 적용할 사실과 선호를 담고, 스킬은 반복할 업무 절차를 담습니다. `hermes-hermory`는 현재 프로필에 있는 메모리 도구를 사용합니다. 별도 메모리 서비스를 설치하지 않습니다.

설치, 터미널:

```bash
hermes -p jiwon skills install kimsanguine/hermes-hermory/skills/hermes-hermory
hermes -p jiwon skills list
```

목록에서 `hermes-hermory`를 확인합니다. 메모리 도구가 없으면 [메모리 설정](https://teamsparta.habix.ai/teamsparta/10th/setup/hermes-memory)을 먼저 마칩니다.

### 1. 내 프로젝트 진행 원칙 말하기

```text hermes
/hermes-hermory 내가 새 기능을 만들자고 하면 누가 언제 불편한지, 지금은 어떻게 해결하는지, 이번에 꼭 필요한지를 먼저 물어봐줘. 이걸 내 프로젝트 진행 원칙으로 기억해줘. 다른 기억은 바꾸지 마.
```

저장할 내용을 보여주거나 승인을 요청하면 한 줄의 뜻이 맞는지 읽습니다. 이미 승인한 내용은 다시 작성하지 않고 해당 범위로 진행합니다. 실제 저장 결과와 저장한 프로필을 확인하세요. 기존 기억 전체를 공개할 필요는 없습니다.

### 2. 새 대화에서 기능을 제안하기

5분 미니 실습: `/exit`로 나가 같은 프로필로 새 대화를 엽니다. 이전 원칙 문장을 다시 붙이지 않고 입력합니다.

```text hermes
내 앱에 채팅 기능을 추가하고 싶어.
```

기대 결과는 채팅 화면부터 만드는 대신 기능이 필요한 상황을 먼저 묻는 것입니다. 아래는 답변 모양의 예시입니다.

```text output
누가 어떤 상황에서 채팅이 필요한가요?
지금은 문의를 어떻게 주고받나요?
이번에 꼭 해결해야 할 불편은 무엇인가요?
```

자신의 상황으로 답하고 이번 기능을 만들지, 다른 방법을 쓸지 직접 결정합니다. 사용자의 판단을 대신해 기능 추가를 확정하는 실습이 아닙니다.

### 3. 원칙을 바꾸거나 점검하기

다음에 기준을 바꾸고 싶다면 전체 기억을 다시 쓰지 말고 해당 원칙만 고칩니다.

```text hermes
/hermes-hermory 방금 저장한 기능 추가 원칙에 “기존 방법을 조금 고쳐도 해결되는지”를 묻는 질문도 넣고 싶어. 그 원칙 한 항목만 바꿀 내용을 먼저 보여줘.
```

수정안이 맞으면 같은 대화에서 그 한 항목만 바꾸도록 승인하고, 실제 저장값을 다시 읽어 확인합니다. 기억 점검은 수정 없이 시작합니다.

```text hermes
/hermes-hermory 이번에 저장한 프로젝트 진행 원칙만 점검해줘. 여러 프로젝트에 계속 쓸 기준인지, 특정 작업의 임시 내용인지 설명해줘. 수정하거나 지우지는 마.
```

막히면: 새 대화가 기준을 따르지 않으면 저장한 프로필과 현재 프로필을 비교하고, 해당 저장값만 다시 읽게 합니다. 도구가 보고한 용량이 부족하면 중복·임시 항목의 정리안을 확인하고 승인한 범위만 바꿉니다. API 키와 고객 자료는 기억에 넣지 않습니다. 연습 기준을 더 쓰지 않을 때는 그 한 줄의 삭제안을 검토한 뒤 승인합니다.

완료 확인: 진행 원칙을 기억시킨 뒤 새 대화에서 채팅 기능을 제안했고, 사용자의 문제를 먼저 묻는지 확인했습니다.

다음에 더 찾아볼 것: [hermes-hermory 공개 스킬](https://github.com/kimsanguine/hermes-hermory).

## 06. hyperframes-cli: 내 프로젝트를 소개하는 15초 영상 만들기 (25분)

프로젝트를 설명할 때 모든 기능을 나열하면 보는 사람이 무엇이 편해지는지 놓치기 쉽습니다. “겪던 문제 → 사용하는 장면 → 달라지는 점” 세 장면으로 소개합니다. HyperFrames는 HTML 장면을 시간표에 맞춰 보여 주고 영상 파일로 만듭니다. 웹사이트 배포와 영상 제작은 다른 결과입니다.

설치 확인과 사전 검사, 터미널:

```bash
hermes -p jiwon skills list
hermes -p jiwon skills inspect heygen-com/hyperframes/skills/hyperframes-cli
```

검사 결과를 읽고 설치할 경우의 명령입니다. 검사 차단이면 강제로 설치하지 않고 아래 대안을 사용합니다.

```bash

```

목록에서 `hyperframes-cli`를 확인합니다. 실제 영상 실행 도구, 브라우저와 렌더용 FFmpeg도 준비돼 있어야 합니다.

### 1. 소개할 자료 전달하기

내 프로젝트 화면 캡처 한 장과 “누구의 어떤 불편을 해결하는가” 한 문장을 대화에 넣습니다. 앞 실습을 하지 않았다면 본인이 소개할 페이지나 화면을 사용하면 됩니다. 화면이 없으면 원한 화면의 설명을 주고 모형 화면임을 표시하게 합니다.

```text hermes
/hyperframes-cli 내가 제공한 화면이나 설명으로 내 프로젝트를 소개하는 15초 영상을 만들고 싶어. 처음에는 해결할 문제, 가운데는 사용 화면, 마지막은 사용하면 편해지는 점을 보여줘. 장면 세 개를 먼저 미리보기로 보여줘.
```

에이전트가 만든 실제 이미지 파일을 열어 봅니다. 문구는 읽히는지, 사용하는 장면이 무엇인지, 약속하지 않은 효과를 만들어 넣지 않았는지 확인합니다. 각 장면의 길이를 함께 받아 총 15초인지 읽으세요.

### 2. 화면과 문구 수정하기

```text hermes
두 번째 장면의 설명을 더 짧게 바꾸고 프로젝트 화면이 잘 보이게 해줘. 수정한 세 장면의 미리보기와 장면별 길이, 실제 파일 위치를 알려줘. 아직 영상으로 만들지는 마.
```

### 3. 확인한 장면을 영상으로 받기

```text hermes
/hyperframes-cli 방금 확인한 구성으로 15초 영상 파일을 만들어줘. 내가 열 수 있는 실제 파일 위치를 알려줘. 장면이 순서대로 바뀌고 문구가 읽히는지 재생해볼게. 공개 업로드는 아직 하지 마.
```

5분 미니 실습: 받은 MP4를 직접 열어 처음, 중간, 마지막 장면을 봅니다. 문구가 잘리거나 너무 빨리 지나가면 그 장면을 말로 지정해 다시 수정합니다.

```text output
첫 장면: 누구의 어떤 불편인지 보여 줌

마지막 장면: 사용하면 편해지는 점 전달
```

<details>
<summary>스캐폴딩, 타임라인과 퍼블리시는 무엇인가요?</summary>

스캐폴딩은 에이전트가 영상 제작에 필요한 기본 파일을 만드는 일입니다. 타임라인은 장면이 언제 시작하고 끝나는지 나타내는 시간표입니다. 프레임은 특정 순간의 화면이고, 렌더는 장면을 실제 영상 파일로 만드는 과정입니다. 수강생은 폴더나 시간 속성을 직접 지정하기보다 장면의 내용과 읽기 좋은 속도를 말하면 됩니다.

퍼블리시는 영상을 웹 링크로 공유하는 별도 작업입니다. 파일을 받았다고 공개 업로드까지 된 것은 아닙니다. 링크가 필요하면 공유 계정·범위를 확인한 뒤 따로 승인합니다.

</details>

막히면: 영상이 만들어지지 않으면 에이전트에게 오류를 전달하고 브라우저와 FFmpeg 등 빠진 준비를 확인하게 합니다. HTML이 열리는 것과 영상 파일이 재생되는 것은 구분합니다.

완료 확인: 세 장면의 실제 미리보기를 열었습니다. 렌더했다면 15초 MP4를 재생했고, 준비가 막혔다면 어디까지 만들었는지 구분했습니다.

다음에 더 찾아볼 것: [HyperFrames 공식 가이드](https://github.com/heygen-com/hyperframes/blob/main/docs/developers/cli.mdx).

## 07. reverse-engineer-anything: 마음에 드는 사이트의 신청 흐름 배우기 (심화 선택, 20분)

마음에 드는 사이트를 찾으면 색과 배치만 보지 말고 “방문자가 무엇을 이해하고 어떤 행동을 하는가”를 봅니다. 이 스킬은 확인 가능한 화면과 동작의 근거를 모아 관찰, 추정, 미확인을 구분합니다. 이번에는 공개 웹페이지에서 볼 수 있는 흐름을 읽습니다. 서버와 DB 구조를 추측하는 과제가 아닙니다.

설치, 터미널:

```bash
hermes -p jiwon skills install morluto/rea/.agents/skills/reverse-engineer-anything
hermes -p jiwon skills list
```

목록에서 `reverse-engineer-anything`을 확인합니다. 스킬 설치와 REA 웹 분석 도구 연결은 별개입니다. 도구가 없으면 먼저 준비 방법을 확인하고 일반 화면 읽기와 REA 분석을 구분합니다. 이 실습 때문에 바이너리 분석 도구를 설치하지 않습니다.

### 1. 공개 사이트와 보고 싶은 이유 전달하기

마음에 드는 공개 URL 한 개와 어떤 점이 좋은지 한 문장을 대화에 넣습니다. 로그인 없이 볼 수 있는 페이지를 고릅니다. 예제가 필요하면 [Tally 공개 홈페이지](https://tally.so/)에서 처음 방문한 사람에게 무엇을 만들 수 있는지 어떻게 설명하는지 봅니다.

```text hermes
/reverse-engineer-anything 방금 준 공개 사이트에서 처음 방문한 사람이 서비스를 이해하고 신청하기까지 어떤 화면과 버튼을 거치는지 살펴봐줘. 내 소개 사이트에 참고할 구성 세 가지와 그 이유를 알려줘. 가입·신청 제출은 하지 마.
```

일반 사이트의 “신청”은 문의나 시작하기 같은 주요 행동을 뜻합니다. Tally에서는 만들기 시작하는 버튼과 그 앞의 설명 흐름을 봅니다. 로그인이나 실제 가입이 시작되면 거기서 멈춥니다.

### 2. 내 사이트에 적용할 구성 고르기

내 소개 페이지가 있다면 같은 대화에 전달합니다. 없다면 원하는 역할과 보여줄 프로젝트 한 개를 문장으로 알려 줍니다.

```text hermes
그중 내 소개 사이트에 필요한 것만 골라 첫 화면부터 문의하기까지 구성안을 만들어줘. 어떤 설명 다음에 어떤 버튼을 둘지 쉬운 말로 써줘. 본 사이트의 문구와 이미지는 그대로 복사하지 마.
```

5분 미니 실습: 직접 공개 사이트를 열어 에이전트가 말한 화면과 버튼을 찾습니다. 제안 세 개 중 내 방문자에게 필요한 한 개를 고르고 그 이유를 한 줄 적습니다.

```text output
관찰: 공개 화면에서 직접 확인한 설명과 버튼 순서
참고할 구성: 내 방문자에게 도움이 되는 세 가지와 이유
내 선택: 이번 소개 사이트에 반영할 한 가지
미확인: 로그인 뒤 화면이나 관찰하지 못한 동작
```

막히면: 사이트 접근이 막히면 공개 화면 캡처로 구조를 읽을 수 있습니다. 이 경우 버튼 뒤 동작과 REA 도구 실행은 확인하지 못했다고 구분합니다. 공개 화면을 봤다는 이유로 비공개 동작을 안다고 쓰지 않습니다.

완료 확인: 공개 화면의 관찰 근거가 있고 내 사이트에 적용할 구성 한 개를 선택했습니다. 도구가 없거나 로그인 뒤라 보지 못한 범위는 구분했습니다.

다음에 더 찾아볼 것: [REA 공식 저장소](https://github.com/morluto/rea).

## 08. 내 결과물 다시 열고 다음 작업 정하기 (10분)

오늘 만든 결과를 직접 다시 열어 봅니다. 모든 실습을 하나의 파일이나 한 프로젝트로 묶을 필요는 없습니다. 같은 소개 페이지의 제작·저장·배포를 연결했다면 실제로 사용한 스킬과 구현 도구가 각각 어떤 일을 맡았는지 설명합니다.

| 실습 | 다시 열어 볼 결과 |
|---|---|
| 문의 기능 | 입력 양식, 실제 접수 위치 또는 미연결 상태 |
| 모임 신청 | 가상 신청 세 건, 운영자 명단과 접근 조건 |
| 포트폴리오 공유 | 다른 창에서 연 실제 배포 주소 |
| 진행 원칙 기억 | 새 대화에서 먼저 받은 질문과 적용한 기준 |
| 소개 영상 | 장면 미리보기와 실제 재생한 영상 |
| 사이트 분석 | 관찰한 화면과 내가 고른 구성 한 개 |

통합 과제로는 소개 사이트에 문의·신청 흐름을 만들고 지인에게 공유하는 작업을 선택할 수 있습니다. Context7으로 현재 도구의 공식 문서를 확인하고, Supabase로 문의를 비공개로 접수하며, Vercel로 실제 주소를 만듭니다. 공개 자료실이 아니라 개인 문의를 받는 화면이므로 명단은 운영자만 읽도록 합니다.

```text hermes
오늘 만든 결과를 다른 사람이 이어서 쓸 수 있게 짧은 안내를 작성해줘. 실제 주소나 파일 위치, 내가 확인한 동작, 아직 연결하지 못한 것, 다음에 할 한 가지를 넣어줘. 키와 로그인 정보는 넣지 마.
```

같은 절차를 내 업무에 옮길 때는 주제보다 기준을 가져갑니다. 받을 정보와 볼 사람, 공유 범위, 기억할 원칙, 보여줄 장면과 근거를 내가 정하고 에이전트에게 구현을 맡깁니다.

완료 확인: 선택한 결과물을 다시 열었고 다른 사람에게 보여줄 위치와 다음 작업을 남겼습니다. 실제로 하지 않은 계정 연결이나 실행을 완료로 쓰지 않았습니다.
